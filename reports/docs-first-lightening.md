# Owner-authorized docs-first simplification

Historical preparation scope. The owner subsequently installed the Claude-style
candidate; [live acceptance and remaining limits](docs-first-live-acceptance.md)
supersede the uninstalled/blocking status recorded below.

The owner explicitly requested a lighter global hook on 9 September 2026.
The intent is to keep gh api available as the primary documentation research
path while preserving relevant installed-source grounding before implementation.
This is authorized hook maintenance, not permission to ignore documentation.

The current docs-first-v2 installation rejects research and ordinary project
operations independently of whether relevant documentation was read. Root observed
shell_unresolved on a combined Git fetch, report read and GitHub PR lookup. The
installed workflow confirms that Git writes, builds/tests, Rust/SQL and unsupported
tools stay blocked even after a signed documentation read. Quoted punctuation is
also rejected before tokenization. Existing Ops Desk pane IDs use wR, which the
numeric-only Herdr target pattern does not accept.

Required lighter behavior:

- Permit gh api documentation and repository research, including release/branch
  discovery followed by immutable source reads. A successful lookup is not proof
  that its contents were read or that a different version is appropriate.
- Permit ordinary Git review, fetch, commit and already-authorized merge/push
  workflows. Project authorization still governs publication and mutations.
- Permit existing builds, tests, formatters and Playwright CLI checks. They do
  not replace documentation or grant live provider authority.
- Permit normal Herdr coordination with actual opaque IDs and literal messages.
- Keep a concise docs-first reminder before implementation. Unsupported Rust,
  SQL or browser APIs need honest manual source grounding instead of a permanent
  workflow block that cannot be satisfied by reading their installed sources.
- Preserve the global instruction to read relevant pinned source, record it in
  the work report and stop an affected implementation when evidence is missing.
- Do not claim semantic enforcement, verified comprehension or an OS security
  boundary. Do not log command bodies, credential values or source contents.

The existing rollout owner is harvest-orchestrator, named in the installed
global report. Root sent the explicit authorization and operational requirements
through its supported named Herdr coordination command. No protected hook file,
trust entry, configuration or evidence store was changed by this report.

The staged reader-access proposal at /tmp/edublend-docs-first-reader-update.py
was read as a proposal only. Its fixed GitHub GET and quoted-literal changes help
research, but it still excludes normal Git operations, tests, Rust/SQL and the
actual Ops Desk pane IDs. It therefore does not by itself satisfy this broader
owner-requested simplification. It has not been executed or installed by root.

Acceptance should demonstrate an actual pinned gh api read, latest-ref discovery,
quoted search and coordination, ordinary Git status/diff plus a disposable commit,
a harmless existing test, and an unsupported-language documentation reminder.
Any retained strict edit gate must have a runnable read-then-edit positive control.
Preserve the previous installation and report exact changed files, tests, active
session behavior and rollback procedure. No product or existing fixture mutation
is part of these hook tests.

Concrete candidate now staged at /tmp/ops-desk-docs-first-lighten.py through a
supported native patch. It transforms the frozen engine without installing or
executing it, keeps the signed reader and supported missing-evidence/maintenance
denials, and permits ordinary workflows with a concise reminder. Unsupported
language/API analysis falls back to explicit manual documentation grounding.
Thirteen synthetic admission probes are included but have not been executed.
The intended policy identifier is docs-first-v3-light.

The existing maintainer has the candidate and is coordinating with the current
EduBlend installation owner. The current reader-only installer is insufficient
for this broader scope. Root also reported two installer review concerns:
verify a reviewed transformer hash before loading it, and never roll back over
a concurrent engine change. No installation or candidate test pass is claimed.
The current hook cannot replace its protected engine through ordinary agent
tools, so the reviewed installer requires one owner-run invocation outside that
gate. This is an execution-path limitation, not a missing user authorization.
