## E1 requirements for the final contract

**E1-1 — Session audience and captured authority.** Specify protected admission for every profile, session, prompt, attach, stop, event and private-artifact operation, not only session creation. Store backend-derived task/session/resource binding and explicit authority kind. Revalidate the captured organization epoch and original authority after asynchronous work; a new request must not renew the old session's authority implicitly. An owner-role credential, task reader, copied conversation ID or agent token cannot become the host operator. Task visibility does not grant private transcript/intermediate-file access.

The existing private [`Principal` and `DelegationGrant`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/business_identity/mod.rs#L61) already distinguish `Operator`, `Credential` and agent lineage. Reuse them: no caller actor/organization fields, fabricated credential ID, nullable-field operator inference or authority reconstruction from task assignment. E1 audit may attribute the mapped protected owner plus operator authority; the shared original token does not identify which individual person used it.

**E1-2 — Durable launch and recovery.** Define the reservation/operation key, canonical request binding, task/domain authority, profile configuration revision, root conversation and generation before launch. Specify launch failure, lost response, process-created/DB-failed, reconnect, cancellation and restart recovery. Reattach/reconcile the same owned attempt; uncertain launch must not blindly create another process. A delayed old generation must not activate a session or commit output after cancellation, authority change or task invalidation. Do not adopt an unrelated legacy run by caller-supplied ID.

[`create_chat_dir_core`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/commands/conversations.rs#L1983) supplies a non-Git directory. [`create_chat_conversation_core`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/commands/conversations.rs#L2154) accepts an existing directory and compensates separate folder/conversation writes; it is not an atomic session reservation. Use a narrow task/session-owned transaction seam and recovery receipt, not a new engine or a claim that this existing helper is atomic.

**E1-3 — Immutable managed bytes and storage recovery.** A tool-output pathname is discovery, not authority. The backend must admit a file from the owned session workspace, reject path escape/symlink or changing-file races, bound its size/type and import the actual bytes into private managed storage. Version identity, digest, producing session/turn/client/model and task provenance must describe those bytes. Managed versions must survive scratch-session cleanup. Preview active documents without granting their scripts the application origin or triggering external fetches; unsupported formats may have an honest controlled download path.

Specify staging → verified immutable bytes → database activation/receipt and safe cleanup. Filesystem and SQLite are not one atomic store. Lost activation responses or uncertain commits require lookup/reconciliation before deletion or another import; cleanup must prove an unreferenced owned staging object. Test a changed source file, retained version 1 after version 2, failed/late writes and lost successful responses.

**E1-4 — Human publication, exact versions and attribution.** The final DTO must submit explicit immutable version references with task CAS and an operation receipt. The task-owned writer must recheck current human submit authority, private version access, destination task/domain and the exact selected byte identities, then commit the deliverable, disclosure references, activity and receipt together. A retry cannot publish a different payload under the old key. Later task review uses the existing human/reviewer policy and exact deliverable revision. Producing agent/model, human submitter and human reviewer are separate facts; agent completion is not human publication or review.

[`submit`/`review`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/business_tasks/store.rs#L570) currently persist a text deliverable and revisioned decision. [`capabilities`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/business_tasks/policy.rs#L8) permit agent submission in the existing text workflow but reserve review to a human. The new human publication seam must enforce its own human requirement without relabelling an agent as the operator or silently changing the old workflow. Publication exposes only selected versions to current task readers, not the session, other versions, private source material or connector credentials.

## Concrete acceptance probes

These are **planned implementation gates**, not executed results.

| Gate | Negative and positive control |
| --- | --- |
| E1 authority | Actual original operator completes the owned flow. Same-org owner-role member, other tenant, missing auth and agent capability fail every host session/private-output operation; copied IDs cannot attach. Suspend/resume or captured credential revocation cannot resurrect an old grant. |
| Session recovery | A real synthetic ACP/PTY process starts once; lost response reconnects to its persistent session. Inject failure after reservation, process launch and activation; cancellation/late callback cannot create an active replacement or publish output. Existing unrelated sessions remain unchanged. |
| Bytes and preview | Import a real document and a second version; verify stored/downloaded digests. Reject foreign/path-escape/changing-file input and unsafe active preview. Scratch removal cannot remove a committed version. Storage/receipt failure and retry retain exactly the intended bytes. |
| Human decision | Two real DB writers race task revision/publication; only one exact version set commits. Revoked authority and agent publication fail with unchanged rows. Lost receipt replay yields the same deliverable; human review accepts/returns it with correct actor and version attribution. |
| Usable protected UI | Actual CLI task → session pane → prompt/output → reconnect/stop → selected document/version → human review, using a local synthetic process and protected API. No login/install/inference merely from opening a pane; no interception presented as a real backend pass. |

## E2 and E3 remain distinct

**E2 is not an E1 blocker, and E1 is not tenant isolation evidence.** Existing host environment preparation includes original configured provider/Git credential custody; generic terminal routes accept shell/cwd/terminal IDs. The companion's [`process_session_info`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/acp/delegation/listener.rs#L715) deliberately resolves arbitrary sessions after token existence. Its cancel path also passes only an external handle into a broker-wide lookup (`listener.rs:703`, `broker.rs:3114`). These are concrete operation/resource prerequisites under the new tenant target, not an assertion that E1 changes accepted legacy authority.

E2 must cover actual dispatcher/token creation, session/event/file operations, terminal input/output, cancellation, authoring and child delegation, with two tenants and an owned positive stream. Global event subscription or filtered tool discovery does not supply that boundary. Profile process/filesystem/credential isolation must be proven separately from cwd/HOME/env selection. [Accepted tenancy analysis](business-multitenancy-review.md) remains applicable. [`NativeSessions`](https://github.com/Adanmohh/codeg/blob/f30a27da45c41ed7593c5da433759af8314a08ef/src-tauri/src/business_identity/native.rs#L1) explicitly keeps restricted tenant windows unavailable because the shared Tauri response-channel boundary is unresolved; original protected platform/native access remains available.

**E3** needs immutable provider/account identity, explicit current read grants, permitted operation families, captured tenant/config/grant epochs and source-scoped refresh ordering. A configured secret is not current account-state proof. Preserve timestamped last-good data while representing stale/denied/unknown state accurately, and withhold data after access revocation. Task/asset publication cannot imply private account access. The final adapter contract needs its own official immutable pin and two-account positive/negative pagination, reordered-refresh and no-write probes. No provider survey or selection was added here.
