## Implemented boundaries

- Each opaque member credential resolves one explicit organization and a private captured Principal. `Principal::authorization_epoch() -> i64` is read-only. Every current authorization checks active organization/current epoch, original credential and membership/domain; an async caller retains its original Principal. Suspend/resume increments lifecycle revision and epoch, so reauthentication cannot rescue an old captured operation. Stored individual DelegationGrant preserves credential lineage and epoch; old missing-epoch grants work only for the explicitly retained original organization at epoch 1.
- Forward `m20260908_000012_business_tenancy` rebuilds the singleton parent on one pinned SQLx connection, preserving original IDs, hashes, history and references. Foreign keys are disabled outside its atomic writer transaction on that same connection, checked before commit, then restored before pool return. Cancellation closes the unrecovered connection. A durable marker supports retry after schema commit but before SeaORM's migration receipt. Lossy down is refused. An immutable mapping selects the original compatibility organization; no first-row fallback, including when another tenant is provisioned before original bootstrap.
- Separate `/api/platform/business/*` routes accept only the existing authenticated operator marker. A role named owner/admin never creates PlatformContext. Create/status/reissue use one writer transaction and immutable platform-attributed operation receipts. Same-operation replay preserves metadata and never re-delivers the bearer. Explicit recovery checks current tenant revision/epoch, current active provisioning human owner/revision and current credential lineage, then atomically revokes that credential and issues one replacement. Other credentials survive. Same-writer last-human-owner protection prevents concurrent demotions from removing every owner.
- `/api/business/settings/{get,update}` uses actual member identity. Human owner/admin writes require ManageTenantSettings, authorization, revision CAS and audit in the same writer transaction. The schema is closed: displayName plus palette neutral|blue|violet, workspaceLayout split|stacked and defaultWorkArea tasks|conversations. Defaults neutral/split/tasks. There are no caller-selected identity, CSS, URL, asset or secret fields. Rebrand owns scoped theme/layout rendering; these preferences grant no engine capability.
- An immutable `business_execution_authority_epoch` sidecar captures the tenant epoch for entrusted A runs. The narrow `business_tasks/agent.rs` authority query requires that epoch to match the current active organization before initial linking or later use. An entrusted-but-unlinked old run cannot revive after suspend/resume. Original individual human delegation is still required separately.
- The native build derives permissions from the actual 553-command registry and checks a closed 26-command tenant allowlist. Native sessions bind the actual invoking window to an in-memory captured Principal; wrong-window/closed handles and cached Principals after logout/switch fail, and member login never falls back to the operator. Existing native business wrappers use the same core; host compatibility remains. Custom controls operate only on the injected caller window, without a target label. No production tenant-window creation endpoint is registered; `business_window_context.tenantWindowAvailable` is false.
